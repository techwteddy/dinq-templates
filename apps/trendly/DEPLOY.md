# Deploying Trendly to Firebase App Hosting

This guide takes you from the current local repo to a live `https://trendly--<id>.web.app` URL on Google's infrastructure.

Total time: **~20 minutes** (first deploy).

---

## 1. Put the code on GitHub

Firebase App Hosting deploys straight from a GitHub branch.

```powershell
cd C:\Trendly
git init
git add .
git commit -m "Initial Trendly commit"
```

Create a new **private** repository at https://github.com/new (name it `trendly`), then connect:

```powershell
git remote add origin https://github.com/<your-username>/trendly.git
git branch -M main
git push -u origin main
```

## 2. Create the Firebase project

1. Go to https://console.firebase.google.com and click **Add project**.
2. Name it `trendly` (or anything). Disable Google Analytics for now if you want to move fast.
3. Once the project is ready, open the sidebar and click **Build -> App Hosting**.
4. Click **Get started** and upgrade to the **Blaze (pay-as-you-go)** plan — App Hosting requires it. Set a budget alert at $5 so you cannot get surprise-billed.

## 3. Install the Firebase CLI

```powershell
npm install -g firebase-tools
firebase login
```

A browser window opens; sign in with the same Google account that owns the Firebase project.

## 4. Store your Supabase secrets

Firebase App Hosting pulls env vars from Google Secret Manager at build and runtime. Create two secrets:

```powershell
cd C:\Trendly
firebase apphosting:secrets:set SUPABASE_URL
# paste:  https://mqwsyylxhozewpjmkyaq.supabase.co   (your NEXT_PUBLIC_SUPABASE_URL)

firebase apphosting:secrets:set SUPABASE_ANON_KEY
# paste:  sb_publishable_...                          (your NEXT_PUBLIC_SUPABASE_ANON_KEY)
```

When prompted, let the CLI grant the App Hosting backend access to each secret (answer **Yes**).

These names match the `secret:` fields in `apphosting.yaml`.

## 5. Create the backend and connect GitHub

```powershell
firebase apphosting:backends:create
```

The CLI will ask you to:
- Pick the Firebase project you just created.
- Pick a region (`us-central1` is cheapest and fastest for most users).
- Give the backend an ID (`trendly` is fine).
- Authorize the Firebase GitHub App on your account.
- Pick the `trendly` repo and the `main` branch.
- Confirm the root directory is `/` (the repo root).

It will kick off the first deploy automatically. Watch the build in the Firebase Console under **App Hosting**.

## 6. Update Supabase with the live URL

Firebase will give you a URL like `https://trendly--<random>.web.app`.

In your Supabase dashboard:
- **Authentication -> URL Configuration**
  - Site URL: your Firebase URL
  - Redirect URLs: add `https://trendly--*.web.app/**` and your custom domain later

Without this, email magic-link logins will bounce back to `localhost`.

## 7. (Optional) Custom domain

In the App Hosting backend settings, click **Add custom domain**, enter your domain, and add the DNS records Firebase shows to your registrar. SSL is issued automatically in a few minutes.

## 8. Ongoing deploys

After the first deploy is wired up, every `git push` to `main` triggers a new build and deploy. No CLI needed.

```powershell
git add .
git commit -m "Change"
git push
```

## 9. Get listed on Google Search

1. Go to https://search.google.com/search-console and **Add property** using your Firebase or custom domain.
2. Verify ownership — the easiest method is the HTML tag: Firebase auto-serves files from `/public/`, so drop the verification file there and push.
3. Submit the sitemap at `/sitemap.xml` (already generated by `src/app/sitemap.ts`).
4. Google typically indexes new sites in 3-14 days. You can speed the first page up by clicking **Request indexing** on the URL inspection tool.

## Reference - files this setup added

| File | Purpose |
| ---- | ------- |
| `apphosting.yaml` | Firebase App Hosting runtime + secrets config |
| `src/app/sitemap.ts` | Auto-generates `/sitemap.xml` |
| `src/app/robots.ts` | Auto-generates `/robots.txt` |
| `src/app/(app)/privacy/page.tsx` | `/privacy` page required for Play Store / Google listing |
| `public/manifest.json` | PWA manifest (also reused if you wrap for Play Store later) |
| `.gitignore` | Expanded to cover Firebase + env artifacts |

## Troubleshooting

**Build fails with "NEXT_PUBLIC_SUPABASE_URL is not defined":** the secret name in `apphosting.yaml` must exactly match what you set via `firebase apphosting:secrets:set`.

**"Auth redirect loops back to localhost":** you forgot Step 6 — add the live URL in Supabase Auth settings.

**Images broken after deploy:** add the Firebase / custom-domain hostname to the `images.remotePatterns` list in `next.config.ts` only if you start serving images from there; Supabase images already whitelisted.

**Need to add an icon:** export a 512x512 PNG as `public/icon-512.png` and a 192x192 PNG as `public/icon-192.png`. Without these, the PWA manifest warning shows in Chrome DevTools but the site still works.
