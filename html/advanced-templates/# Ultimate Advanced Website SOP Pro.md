# 3. Three.js / WebGL SOP Usage

Use these files whenever the site includes a 3D, WebGL, canvas, shader, Spline, or immersive background effect.

## `3d-web-experience.md`
Use this to decide whether the project should use:
- Vanilla Three.js
- React Three Fiber
- Spline
- WebGL
- A lighter canvas-only system

For single-file HTML projects, prefer vanilla Three.js unless the user specifically requests React/Next.

## `threejs-fundamentals.md`
Use this for:
- Scene setup
- Camera
- Renderer
- Resize handling
- Animation loop
- Object hierarchy
- Pixel ratio
- Mobile-safe rendering

Every Three.js background must have clean setup and resize logic.

## `threejs-geometry.md`
Use this for:
- Particle geometry
- Spheres
- Planes
- Tubes
- Helixes
- Instanced shapes
- Custom BufferGeometry
- Performance-friendly geometry

Use BufferGeometry for particle systems and custom backgrounds.

## `threejs-materials.md`
Use this for:
- MeshStandardMaterial
- MeshPhysicalMaterial
- PointsMaterial
- ShaderMaterial
- Transparent materials
- Emissive materials
- PBR-like depth

Materials must support the mood of the site.

## `threejs-lighting.md`
Use this for:
- Ambient lighting
- Directional lighting
- Point lighting
- Hemisphere lighting
- Glow mood
- Shadow decisions
- Environment lighting

Do not over-light the scene. Make it cinematic.

## `threejs-textures.md`
Use this for:
- CanvasTexture glow sprites
- Texture color space
- Repeating textures
- Noise textures
- Video textures if needed
- Environment maps if needed

Use procedural canvas textures for particles where possible.

## `threejs-animation.md`
Use this for:
- Procedural object motion
- Time-based animation
- Particle breathing
- Rotation
- GLTF animation if models exist
- Mixer logic if imported models are used

Animations must feel alive but not chaotic.

## `threejs-interaction.md`
Use this for:
- Mouse movement influence
- Pointer movement parallax
- Click shockwaves
- Raycasting
- Object hover/click interactions
- Camera controls only when useful

At minimum, the background should respond subtly to mouse movement.

## `threejs-shaders.md`
Use this for:
- ShaderMaterial
- Uniforms
- Time-based color effects
- Fresnel effects
- Vertex displacement
- Procedural gradients
- Custom fragment effects

Use shaders when the site needs a more premium, non-template visual effect.

## `shader-programming-glsl.md`
Use this for:
- Raw GLSL logic
- Vertex shader structure
- Fragment shader structure
- Uniforms
- Varyings
- Noise
- UV effects
- GPU-driven visuals

Use this when creating custom visual effects beyond normal materials.

## `threejs-postprocessing.md`
Use this for:
- Bloom
- Glow
- FXAA/SMAA
- Depth of field
- Color grading
- Vignette
- Film grain
- EffectComposer

If true post-processing is too heavy for the project, simulate bloom carefully with CSS filters and additive particles.

## `spline-3d-integration.md`
Use this when:
- A Spline scene is requested
- The project needs fast 3D without writing the whole scene
- A Spline embed fits better than custom Three.js

If no Spline URL is provided, do not invent one. Leave a placeholder.

## `fixing-motion-performance.md`
Use this as the final animation QA file.

Follow:
- Animate transform and opacity first
- Avoid animating width/height/top/left
- Avoid layout thrashing
- Avoid scroll event jank
- Use IntersectionObserver
- Use requestAnimationFrame carefully
- Respect prefers-reduced-motion
- Pause/limit offscreen animations
- Use will-change surgically
- Avoid continuous blur/filter animation on large surfaces

# 6. Required Output Quality

The final website must include:

## Visual Requirements
- Non-generic hero layout
- Strong visual atmosphere
- Premium typography
- Intentional color system
- Custom section structures
- No repeated card layouts
- No lazy gradient blob backgrounds
- No random stock-looking placeholder design
- No centered hero with two buttons as the only idea

## Motion Requirements
- Cinematic hero entrance
- Staggered section reveals
- Interactive hover states
- Custom cursor
- Scroll progress or side nav
- At least one marquee/ticker
- Background responds to mouse or scroll
- Motion must use transform/opacity where possible

## Background Requirements
- Use Three.js/canvas/WebGL when appropriate
- Use the selected `BACKGROUND-SYSTEMS.md` pattern
- Match colors to the brand
- Avoid heavy performance problems
- Support reduced motion
- Keep content readable above the background

## Interaction Requirements
- Buttons must feel physical
- Cards/rows/panels must react uniquely
- Cursor must react to interactive elements
- Forms must have polished focus states
- Mobile interactions must still work without hover

## Mobile Requirements
- No horizontal overflow
- Hero must fit small screens
- Multi-column layouts collapse cleanly
- Canvas background must not kill mobile performance
- Touch targets must be at least 44px
- Avoid `h-screen`; use `min-height: 100dvh`

# 7. Build Process Claude Must Follow

When using this SOP, follow this process:

## Step 1 — Read the Website Brief
Identify:
- Business type
- Audience
- Primary conversion goal
- Brand personality
- Desired emotion
- Content sections
- Technical format

## Step 2 — Choose the Design Stack
Use `SKILLS-INDEX.md` to choose:
- Main UI style
- Motion style
- Background style
- Interaction style

## Step 3 — Create a Visual Philosophy
Use `canvas-design.md` and `visual-emotion-engineer.md`.

Output internally:
- Visual movement name
- Target emotion
- Color logic
- Typography logic
- Spatial logic
- Interaction logic

## Step 4 — Select Background System
Use:
- `BACKGROUND-SYSTEMS.md`
- `3d-web-experience.md`
- Three.js SOPs

Choose the best background for the industry.

## Step 5 — Design Sections
Each section must use a different structure.

Possible section structures:
- Split hero
- Editorial story block
- Asymmetric bento
- Horizontal panel strip
- Full-width hover rows
- Data/stat band
- Quote wall
- Process timeline
- Floating dashboard/mockup
- Terminal panel
- Contact system

Do not repeat the same structure twice.

## Step 6 — Add Motion and Interaction
Use:
- `high-end-visual-design.md`
- `design-spells.md`
- `animejs-animation.md`
- `magic-animator.md`
- `antigravity-design-expert.md`

Every important interactive element needs a premium state.

## Step 7 — Apply Performance QA
Use:
- `fixing-motion-performance.md`
- `threejs-fundamentals.md`
- `threejs-postprocessing.md`

Confirm:
- No layout-thrashing animations
- No broken scroll handling
- No overdone blur
- No huge promoted layers everywhere
- Reduced motion supported
- Mobile performance considered

## Step 8 — Final Self-Check
Before giving the final code, answer these internally:

1. Did I use every uploaded SOP file in the design/build process?
2. Does this look better than the demo HTML files?
3. Does it move better than the demo HTML files?
4. Does it interact better than the demo HTML files?
5. Does every section feel custom?
6. Is the background matched to the brand?
7. Are hover/focus/mobile states polished?
8. Is the code self-contained if requested?
9. Are the animations performance-safe?
10. Would this feel expensive to a client?
